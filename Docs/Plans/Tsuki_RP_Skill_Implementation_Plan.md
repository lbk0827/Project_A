# 츠키 RP 전용 스킬 구현 계획

## 1. 목표

츠키의 전용 자원을 기존 EP에서 RP(Rage Point)로 교체하고, 데이터 테이블 기반의 RP 축적·소비 시스템과 전용 스킬 `달빛 베기(MOON SLASH)`를 구현한다.

본 기능은 다른 캐릭터의 RP 설정과 전용 스킬을 행 추가만으로 확장할 수 있도록 수치와 런타임 식별자를 데이터 테이블에서 관리한다.

## 2. 확정된 게임 규칙

### RP

- 최대 RP: `7`
- 정식 전투 시작 RP: `0`
- 프로토타입 전투 시작 RP: `3`
- 적 1마리 처치: `+1 RP`
- 실제 행동 포인트 1 소비: `+0.25 RP`
  - 카드 할인 적용 후 실제 소비량을 사용한다.
  - 비용 0 카드는 RP를 획득하지 않는다.
- 플레이어가 End Turn을 누른 시점: `+0.5 RP`
- RP는 최대치를 초과하지 않는다.
- RP 스킬 사용은 적 행동 카운트를 감소시키지 않는다.

프로토타입 검증이 끝나면 테이블의 시작 RP만 `3`에서 `0`으로 되돌린다.

### MoonSlash

- 스킬 ID: `moon_slash`
- 표시 이름: `달빛 베기`
- 영문 이름: `MOON SLASH`
- 소비 RP: `3`
- 사용 가능 조건: 현재 RP가 소비 RP 이상
- 최대 RP 7에서는 두 번 사용 가능하며 두 번 사용 후 RP 1이 남는다.
- 대상: 모든 살아 있는 적
- 피해: `공격력 × n%`를 모든 적에게 총 5회 적용
- 프로토타입의 `n` 기본값: `100` (테이블에서 즉시 조정 가능)
- 5회의 참격마다 치명타를 독립 판정한다.
- 일반 공격력 강화 버프와 치명타 배율을 각 참격에 적용한다.

## 3. 데이터 테이블 설계

새 워크북 `CharacterRPSkills.xlsx`에 다음 시트를 둔다.

### `character_rp_settings`

| 필드 | 형식 | 설명 |
| --- | --- | --- |
| `character` | key,string | 캐릭터 ID |
| `max_rp` | float | 최대 RP |
| `starting_rp` | float | 전투 시작 RP. 프로토타입은 3 |
| `rp_per_enemy_kill` | float | 적 처치당 획득 RP |
| `rp_per_action_point` | float | 실제 행동 포인트 1 소비당 획득 RP |
| `rp_per_end_turn` | float | End Turn 입력당 획득 RP |

### `character_rp_skills`

| 필드 | 형식 | 설명 |
| --- | --- | --- |
| `id` | key,string | 스킬 ID |
| `character` | string | 캐릭터 ID |
| `display_name` | string | 한글 표시 이름 |
| `display_name_en` | string | 영문 표시 이름 |
| `rp_cost` | float | 소비 RP |
| `damage_percent` | float | 1타당 공격력 배율 |
| `hit_count` | int | 참격 횟수, 현재 5 |
| `target` | string | `all_enemies` |
| `motion_animation` | string | `MoonSlash` |
| `vfx_id` | string | MoonSlash VFX ID |
| `cutin_hold_seconds` | float | 컷인 정지 시간 |

Excel은 기존 테이블 내보내기 규약에 따라 `data/generated/character_rp_settings.json`과 `data/generated/character_rp_skills.json`으로 변환한다.

## 4. UI 및 입력 흐름

1. 왼쪽 EP 표기를 `RP / RAGE POINT`로 변경한다.
2. RP 게이지는 0.25 단위를 표현할 수 있는 연속형 채움과 숫자 표기를 사용한다.
3. 게이지 옆에 츠키의 작은 초상화 버튼을 표시한다.
4. RP가 스킬 비용 이상이면 초상화 버튼을 활성화하고 발광/펄스 연출을 적용한다.
5. 초상화 클릭 시:
   - 전용 스킬 카드 표시
   - 초상화 자리를 `취소` 버튼으로 전환
   - 모든 살아 있는 몬스터에 AIM 강조 표시
6. 강조된 몬스터 중 하나를 클릭하면 전체 공격을 확정한다.
7. 취소 버튼, 우클릭 또는 유효하지 않은 상태 전환 시 선택 상태를 안전하게 해제한다.
8. 전투 연출 중에는 카드, End Turn, RP 스킬과 몬스터 입력을 잠근다.

## 5. MoonSlash 실행 시퀀스

1. RP 비용 차감 및 RP 선택 UI 닫기
2. 전투 입력 잠금과 화면 암전
3. 츠키 대형 초상화가 화면 왼쪽에서 진입
4. 약 1초 정지
5. 초상화가 화면 위로 이동하며 퇴장
6. 츠키가 몬스터 방향으로 달려 화면 중앙의 필살기 위치에 정지
7. `MoonSlash` 캐릭터 애니메이션 재생
8. 모든 살아 있는 몬스터에게 달 VFX 동시 생성
9. 5개의 참격 타이밍에 맞춰 달 균열 단계와 피해 5회 처리
10. 달이 조각나고 파편·섬광과 함께 소멸
11. 츠키가 원래 위치로 복귀
12. 전투 입력 복구

## 6. VFX 리소스 계획

기존 5연베기 검기 스프라이트를 보조 궤적으로 재사용하되, 다음 요소를 추가한다.

- 달 본체와 외곽 광륜
- 1~5단계 균열 표현
- 최종 분할된 달 조각
- 참격 섬광과 파편
- 등장·균열·분할·소멸을 제어하는 재사용 가능한 Godot VFX 씬

각 몬스터의 화면 크기에 대응하도록 VFX 크기를 설정하고, 모든 적에게 동시에 재생해도 피해 타이밍이 동일하도록 시퀀스를 중앙에서 제어한다.

## 7. 구현 순서

1. 데이터 테이블과 JSON 생성
2. 런타임 RP 설정/스킬 데이터 로더 추가
3. RP 축적·상한·소비 및 전투 이벤트 연결
4. RP 게이지와 초상화/취소/스킬 카드 UI 구현
5. 전체 적 AIM 상태 및 클릭 확정 구현
6. 컷인과 츠키 중앙 이동 시퀀스 구현
7. MoonSlash 애니메이션 이름 연결과 5타 피해 구현
8. 달 분할 VFX 제작 및 통합
9. 테이블 내보내기 검증, Godot 헤드리스 검사, 전투 스모크 테스트

## 8. 완료 조건

- 모든 RP 수치와 MoonSlash 핵심 수치가 테이블 변경만으로 조정된다.
- 프로토타입 시작 RP 3으로 전투 진입 직후 MoonSlash를 테스트할 수 있다.
- RP 축적 세 경로와 최대치 제한이 정상 동작한다.
- 선택/취소/전체 AIM/몬스터 클릭 확정이 충돌 없이 동작한다.
- MoonSlash는 적 행동 카운트를 감소시키지 않는다.
- 각 적에게 5회 피해가 적용되고 각 타격에 공격력 버프와 독립 치명타가 반영된다.
- 컷인, 중앙 이동, MoonSlash, 모든 적 VFX, 복귀가 순서대로 완료된다.
- 전투 종료·적 사망·연출 중 입력 등 경계 상황에서 선택 상태나 입력 잠금이 남지 않는다.

## 9. 프로토타입 검증 기록

- RP 워크북 전체 시트 렌더 및 가독성 확인 완료
- Excel → JSON 내보내기와 RP 테이블 스키마 검증 완료
- RP 런타임 `res://` 참조와 `MoonSlash` 애니메이션 이름 확인 완료
- 달 텍스처 RGBA/투명 모서리 검증 완료
- `git diff --check` 통과
- 현재 작업 환경에 Godot 실행 파일이 없어 엔진 헤드리스 파싱과 실제 전투 재생 검증은 미실행

Godot Editor에서 프로젝트를 처음 열면 신규 달 PNG와 스크립트의 import/UID 파일이 생성된다. 이후 전투 진입 즉시 시작 RP 3으로 컷인, 전체 AIM, 5타, 복귀와 UI 잠금 해제를 직접 확인한다.
