# 카오스 제로 나이트메어 핸드 UI 연출 분석 및 구현 계획

## 1. 목적

레퍼런스 영상 `ScreenRecording_07-13-2026 18-43-34_1.MP4`를 기준으로 전투 화면의 카드 덱·무덤 덱 UI와 카드 이동 연출을 개선한다.

적용 목표는 다음 세 가지다.

1. 카드 덱과 무덤 덱을 작고 정돈된 카운터 UI로 변경한다.
2. 드로우 시 완성된 카드가 덱에서 날아오는 대신, 빛의 궤적이 먼저 이동하고 카드가 화면 하단에서 재질화되도록 한다.
3. 카드 사용 및 End Turn 시 버려지는 카드가 소멸한 뒤 입자로 변환되어 무덤 덱에 흡수되도록 한다.

## 2. 레퍼런스 영상 분석

영상 해상도는 1558×720, 실제 게임 구간은 약 8초다.

### 덱·무덤 UI

- 카드 한 장의 전체 UI를 축소해 두기보다 작은 카드 실루엣과 숫자를 조합한다.
- 화면 가장자리에 붙어 있어 전투 영역을 거의 가리지 않는다.
- 실제 카드 대비 아이콘 크기는 약 25~30%다.
- 카운트 변화 시 짧은 발광과 확대 반응이 있어 시선이 자연스럽게 이동한다.

### 카드 버리기

- 약 2.1초부터 손패 카드가 하단으로 가라앉으며 발광·소멸한다.
- 카드가 사라진 자리에서 여러 개의 청색 광구와 트레일이 발생한다.
- 입자는 직선이 아닌 서로 다른 곡률의 곡선으로 우측 무덤 덱에 수렴한다.
- 약 2.7초에 흡수 플래시와 함께 연출이 종료된다.
- 여러 장은 한 장씩 직렬 처리하지 않고 짧은 간격을 둔 병렬 연출로 처리한다.

### 카드 드로우

- 약 5.2초에 덱 방향에서 광구와 청색 곡선 트레일이 먼저 출발한다.
- 완성된 카드 UI가 덱에서 직접 이동하지 않는다.
- 빛이 화면 하단 핸드 레일 안쪽에 도착한 뒤 카드가 아래에서 위로 재질화된다.
- 여러 장은 약 0.05~0.08초 간격으로 등장하며 전체 연출은 약 0.8~1초 이내다.

## 3. 현재 프로젝트 구조와 차이

### 덱 UI 크기

`deck_hand.tscn`은 248×330 크기의 원본을 `battle_ui.gd`에서 0.5배로 표시한다. 실제 화면 점유 크기는 약 124×165로 레퍼런스보다 크다. 무덤 덱은 루트 크기와 내부 텍스처·카운트 좌표가 서로 달라 유지보수도 어렵다.

### 드로우

`ingame.gd::_play_draw_card_from_deck()`은 완성된 `CardView` 복제본을 덱 중앙에 만들고 손패 위치까지 Tween한다. 레퍼런스의 빛 선행 이동과 하단 재질화 단계가 없다.

### 버리기

`_play_card()`와 `_discard_hand()`는 카드 데이터를 즉시 `discard_pile`로 옮긴다. 이후 `_refresh_ui()`가 기존 손패 노드를 전부 삭제하므로 소멸 애니메이션을 재생할 카드가 남지 않는다.

## 4. 구현 설계

### Compact Pile UI

- 덱과 무덤 덱의 실제 아이콘 크기를 약 42×56으로 통일한다.
- 카운트는 18px 전후로 유지한다.
- 부모 `scale` 대신 씬 자체가 최종 표시 크기를 갖도록 한다.
- 연출이 도착하는 정확한 아이콘 중심 좌표를 외부에 제공한다.
- 카드가 흡수되거나 드로우될 때 아이콘이 짧게 확대·발광한다.

### CardTransferVfx

- 전체 화면 크기의 입력 무시 `Control` 노드로 구현한다.
- 2차 베지어 곡선을 따라 이동하는 광구를 직접 그린다.
- 진행도가 다른 다중 트레일과 작은 스파크를 함께 표시한다.
- 도착 시 확산 링과 플래시를 표시한 후 자동으로 제거한다.
- 정확한 목적지 수렴을 위해 `GPUParticles2D` 단독 사용 대신 스크립트 제어 궤적을 사용한다.

### 드로우 시퀀스

1. 드로우할 카드 데이터를 손패에 추가하고 목표 슬롯을 투명하게 예약한다.
2. 덱 아이콘에서 목표 슬롯 아래의 하단 진입점으로 빛을 이동시킨다.
3. 빛이 도착하면 카드 복제본을 하단 진입점에서 생성한다.
4. 카드의 알파, 크기, 위치를 동시에 보간해 목표 슬롯에 안착시킨다.
5. 여러 장은 짧은 스태거를 적용해 병렬 처리한다.

### 버리기 시퀀스

1. 데이터 변경 전에 현재 카드의 위치·회전·내용을 가진 연출용 복제본을 만든다.
2. 실제 손패 데이터와 UI를 갱신한다.
3. 복제본을 아래로 가라앉히며 축소·발광·페이드한다.
4. 카드 중심에서 무덤 덱으로 곡선 입자를 이동시킨다.
5. 도착 시 무덤 덱 카운터에 흡수 펄스를 적용한다.

End Turn에서는 대상 카드들을 약 0.055초 간격으로 병렬 처리하고, 연출이 종료된 뒤 적 행동 카운트를 진행한다. 보존 카드는 대상에서 제외한다.

## 6. 검증 기준

- 1280×720에서 덱·무덤 UI가 손패 및 End 버튼을 가리지 않는다.
- 턴 시작 드로우에서 완성된 카드가 덱에서 직접 날아오지 않는다.
- 드로우 카드가 핸드 레일 아래에서 나타나 목표 슬롯에 안착한다.
- 사용 카드와 End Turn 카드가 순간 삭제되지 않는다.
- 보존 카드가 End Turn 연출에 포함되지 않는다.
- 연출 중 중복 입력이 차단되고 적 턴이 연출보다 먼저 시작하지 않는다.
- 덱·무덤 카운트와 실제 배열 크기가 항상 일치한다.

## 7. 구현 완료 내용

- 덱·무덤 덱을 42×56 아이콘과 18px 카운트로 축소했다.
- 덱과 무덤 덱이 연출 도착 좌표 및 흡수 펄스를 제공하도록 통일했다.
- 카드 이동 광구, 다중 곡선 트레일, 스파크, 도착 링을 구현했다.
- 카드 영역을 격자로 분해한 입자화·재질화 경계 연출을 구현했다.
- 턴 시작 드로우와 카드 효과의 일반·타입 지정 드로우가 동일한 연출을 사용한다.
- 드로우 카드는 핸드 레일 아래에서 생성되어 레일 위로 올라온다.
- 카드 사용 및 End Turn 시 연출용 복제본을 보존하고, 실제 UI 갱신 후에도 소멸 연출을 끝까지 재생한다.
- 보존 카드는 End Turn 버리기 및 입자 연출에서 제외한다.
- 무덤 카운트는 데이터 이동 시점이 아니라 입자가 무덤에 도착한 시점에 한 장씩 증가한다.
- 무덤을 덱으로 다시 섞을 때 역방향 다중 트레일과 덱 펄스를 재생한다.
- 카드 연출 중 전투 입력과 적 행동 진행을 차단한다.
- Godot 파싱과 자동 스모크 검사에서 턴 시작 드로우, 추가 드로우, 카드 사용, End Turn, 리셔플 경로를 실행했다.
