# Yuki Run 스프라이트 문제점 및 GPT 개선 요청서

## 1. 문서 목적

이 문서는 Yuki의 `Run` 애니메이션에서 좌우 발 교차가 계속 잘못 표현되는 문제를 다음 작업자 또는 GPT에게 전달하기 위한 진단 문서입니다.

현재 결과물을 정답으로 간주하면 안 됩니다. 특히 V8/V9 작업노트에 적힌 오른발/왼발 판정은 검증되지 않은 가정에 기반하므로 참고 자료로만 사용해야 합니다.

이번 문서 작성 단계에서는 스프라이트를 추가 수정하지 않습니다. 먼저 Tsuki의 원본 Run 프레임에서 해부학적 오른쪽/왼쪽 다리를 확정해야 합니다.

## 2. 사용자가 확정한 기준

- Tsuki의 Run은 첫 프레임부터 오른발을 사용합니다.
- Yuki도 Tsuki와 같은 발 순서와 다리 교차를 사용해야 합니다.
- 단순히 양발의 간격이 넓은 자세가 아니라, 오른발과 왼발이 실제로 교대로 앞으로 나오는 동작이어야 합니다.
- 화면에서 어느 쪽에 발이 놓였는지만 비슷해서는 안 됩니다. 골반에서 시작해 무릎과 발목으로 이어지는 동일한 다리의 흐름이 프레임 사이에서 유지돼야 합니다.
- `Walk`는 현재 중요하지 않습니다. 우선 `Run`만 정확하게 개선하면 됩니다.

## 5. 현재 핵심 문제

### 5.1 해부학적 오른발을 먼저 확정하지 않음

기존 작업에서는 Tsuki의 다리를 골반부터 추적하지 않고 화면 왼쪽/오른쪽의 실루엣만 비교했습니다. 이 때문에 화면에서 비슷한 위치에 다리가 있어도 실제로는 반대쪽 다리가 배치될 수 있습니다.

사용자가 알려 준 확정 기준은 "Tsuki Run 16번은 오른발부터 시작한다"입니다. 기존 작업은 이 기준을 정확히 반영하지 못했습니다.

### 5.2 검은 허벅지 스트랩에 대한 잘못된 가정

V8/V9에서는 Yuki의 검은 허벅지 스트랩이 있는 다리를 임의로 오른쪽 다리라고 가정했습니다. 그러나 캐릭터 설정 또는 정면 기준 이미지로 이 가정을 확인하지 않았습니다.

따라서 다음 내용은 현재 신뢰하면 안 됩니다.

- "스트랩이 있는 다리 = 오른쪽 다리"
- "화면 왼쪽 다리 = 오른쪽 다리"
- "화면 오른쪽 다리 = 왼쪽 다리"

오른쪽/왼쪽 다리는 반드시 골반, 무릎 방향, 발등 방향, 의상 레이어를 함께 보고 판정해야 합니다.

### 5.3 포즈 유사성과 발 순서를 같은 것으로 판단함

현재 Yuki 프레임은 Tsuki와 대략적인 보폭과 실루엣이 유사합니다. 하지만 이것만으로 같은 발을 사용한다고 볼 수 없습니다.

다음 두 조건이 모두 만족돼야 합니다.

1. 같은 프레임에서 Tsuki와 Yuki의 해부학적 오른발/왼발 위치가 일치해야 합니다.
2. 연속 프레임에서 같은 다리가 골반-무릎-발목 순서로 자연스럽게 이동해야 합니다.

현재 결과는 첫 번째 조건부터 사용자 검수를 통과하지 못했습니다.

### 5.4 프레임을 독립 생성하여 다리 소유 관계가 끊김

V9는 16~21번을 각각 별도 이미지로 생성했습니다. 개별 이미지는 달리는 자세처럼 보이지만, 이미지 생성 모델은 이전 프레임의 특정 다리를 동일한 다리로 기억하지 않습니다.

그 결과 다음 문제가 발생할 수 있습니다.

- 오른쪽 다리가 다음 프레임에서 왼쪽 다리로 바뀜
- 허벅지는 한쪽 다리인데 무릎 아래가 반대쪽 다리로 연결됨
- 치마 천 뒤에서 두 다리의 깊이 순서가 바뀜
- 동일한 발만 반복해서 앞으로 나오는 것처럼 보임
- 다리 교차 순간에 한쪽 다리가 사라지거나 합쳐짐

### 5.5 치마와 전면 천이 골반 연결부를 가림

Yuki의 파란색/흰색 전면 천이 양쪽 허벅지 시작점을 많이 가립니다. 이 상태에서는 발 위치가 달라도 어느 골반에서 시작한 다리인지 판독하기 어렵습니다.

해부학을 확정하기 전에는 작업용 이미지에서 천을 임시로 걷어 내거나 반투명하게 표시해야 합니다. 다리 동작이 확정된 후 마지막 단계에서 천과 옷자락을 다시 그리는 편이 안전합니다.

### 5.6 정적 비교 이미지만으로 성공 판정

기존 검수는 주로 6프레임 접촉 시트를 눈으로 비교했습니다. 정적 접촉 시트에서는 각 포즈가 달리는 모습인지 확인할 수 있지만, 같은 다리가 시간에 따라 어떻게 이동하는지는 놓치기 쉽습니다.

최종 판정에는 최소한 다음 자료가 필요합니다.

- 느린 속도 `4 FPS` GIF
- 실제 속도 `12 FPS` GIF
- 이전/현재/다음 프레임을 겹친 onion-skin 이미지
- 오른쪽 다리와 왼쪽 다리를 서로 다른 색으로 표시한 추적 이미지

### 5.7 21번 리셋 프레임의 루프 연결

21번은 달리기보다 서 있는 리셋 자세에 가깝습니다. `21 -> 16` 전환에서 상체 기울기와 다리 높이가 크게 바뀌면 달리다가 잠깐 멈추는 느낌이 생길 수 있습니다.

Tsuki의 원본 구성을 그대로 유지할지, Yuki Run에서는 21번을 제외하거나 새로운 연결 프레임으로 바꿀지도 별도로 검토해야 합니다. 단, 발 순서 문제를 먼저 해결한 뒤 판단해야 합니다.

## 6. 기존 시도와 실패 원인

### V6

- Tsuki와 동일한 `4x12` 레이아웃 및 프레임 수를 적용했습니다.
- 레이아웃은 맞았지만 Run의 좌우 발 동작은 해결하지 못했습니다.

### V7

- Tsuki Run 16~21의 포즈를 참고해 Yuki Run 스트립을 한 번에 생성했습니다.
- 모델이 다리 위치를 대략 따라 했지만, 동일한 발만 반복해서 나오는 문제가 남았습니다.

### V8

- 17번 프레임에서 허벅지 스트랩 위치만 옮겼습니다.
- 해부학적 동작을 바꾸지 않은 표면적인 수정이었으며, 잘못된 다리 가정을 강화했습니다.

### V9

- Tsuki의 각 프레임을 별도 포즈 기준으로 사용해 6장을 독립 생성했습니다.
- 프롬프트에서 좌우 다리를 명시했지만 그 좌우 판정 자체가 검증되지 않았습니다.
- 독립 생성 방식이라 프레임 사이 동일한 다리의 연속성을 보장하지 못했습니다.
- 결과적으로 사용자 기준인 "Tsuki처럼 첫 프레임부터 오른발 사용" 검수를 통과하지 못했습니다.

## 7. 다음 작업자가 먼저 해야 할 일

### 단계 A: 생성 전에 분석만 수행

1. Tsuki Run 16~21을 각각 `4x` 이상 확대합니다.
2. 각 프레임에서 골반 중심, 오른쪽 무릎, 오른쪽 발목을 연결합니다.
3. 왼쪽 다리도 같은 방식으로 연결합니다.
4. 오른쪽 다리는 빨간색, 왼쪽 다리는 청록색처럼 고정된 색으로 표시합니다.
5. 바닥에 닿은 발에는 `CONTACT`, 공중에 있는 발에는 `AIR`를 표시합니다.
6. 프레임별 판정표와 주석 이미지를 사용자에게 먼저 보여 줍니다.
7. 사용자가 16번 오른발 판정을 승인하기 전에는 Yuki 이미지를 생성하지 않습니다.

### 단계 B: Yuki의 다리 기준 확정

1. Yuki의 정면 또는 3/4 기준 이미지에서 해부학적 오른쪽/왼쪽 다리를 확인합니다.
2. 허벅지 스트랩이 어느 다리에 있는지 확정합니다.
3. 확정된 표식을 작업 문서에 기록합니다.
4. 스트랩이 의상 연출상 프레임마다 가려질 수 있다면, 작업용 색상 마커를 발목 또는 신발에 임시로 추가합니다.

### 단계 C: 프레임 제작

1. Tsuki의 색상 주석 골격을 Yuki 프레임에 먼저 옮깁니다.
2. 다리와 골반을 먼저 완성하고 상체, 머리카락, 검, 옷자락 순으로 작업합니다.
3. 가능하면 6장을 독립 생성하지 말고 한 프레임을 기준으로 다음 프레임을 편집/inpaint합니다.
4. 프레임마다 오른쪽 다리 마커가 같은 다리를 따라가는지 검사합니다.
5. 골반과 캐릭터 중심이 불필요하게 좌우로 흔들리지 않도록 정렬합니다.

### 단계 D: 검수

1. `4 FPS`와 `12 FPS` GIF를 모두 제작합니다.
2. 프레임별 오른발/왼발 좌표를 표로 남깁니다.
3. 오른발과 왼발의 화면 X 좌표가 주기적으로 교대하는지 확인합니다.
4. 같은 발이 연속 접지하지 않는지 확인합니다.
5. 치마 뒤에서 다리가 합쳐지거나 소유 관계가 바뀌지 않는지 확대 검사합니다.
6. 사용자에게 GIF와 색상 추적표를 함께 보여 주고 승인받습니다.

## 8. 완료 조건

다음 조건을 모두 만족해야 완료로 판정합니다.

- 사용자가 Tsuki 16번의 오른발 판정에 동의했습니다.
- Yuki 16번이 동일한 해부학적 오른발로 시작합니다.
- 오른쪽/왼쪽 다리가 프레임 16~21 전체에서 동일하게 추적됩니다.
- 양발이 교대로 전방 이동 및 접지합니다.
- 한쪽 발만 반복해서 내딛는 느낌이 없습니다.
- 골반-무릎-발목 연결이 모든 프레임에서 해부학적으로 유효합니다.
- 치마나 옷자락이 다리 연결을 모호하게 만들지 않습니다.
- `4 FPS`에서 다리 교차가 읽히고 `12 FPS`에서 자연스럽게 달립니다.
- `21 -> 16` 루프에서 멈춤이나 순간 이동이 없습니다.
- 캐릭터 크기, 발 기준선, 얼굴, 머리카락, 검, 의상 디자인이 안정적입니다.
- 최종 시트는 `724x2172`, RGBA, `181x181` 셀 규격을 유지합니다.

## 9. GPT에게 전달할 분석 요청문

아래 요청문을 먼저 사용하십시오. 이 단계에서는 이미지나 파일을 수정하지 않습니다.

```text
Yuki의 Run 스프라이트를 개선하기 전에 Tsuki 원본의 좌우 다리부터 분석해 주세요.

중요한 사용자 기준:
- Tsuki Run은 첫 프레임 16번부터 해부학적 오른발을 사용합니다.
- 화면 왼쪽/오른쪽 위치를 해부학적 오른쪽/왼쪽으로 임의 변환하면 안 됩니다.
- 기존 V8/V9 문서의 "검은 허벅지 스트랩이 오른쪽 다리"라는 설명은 검증되지 않은 가정이므로 신뢰하지 마세요.

대상 파일:
- Tsuki: project-a/assets/characters/spritesheets/tsuki_spritesheet.png
- Yuki: project-a/assets/characters/spritesheets/yuki_spritesheet.png
- 비교 자료: Docs/ArtSource/characters/spritesheets/yuki/v9/yuki_v9_run_cycle_check.png

Run 프레임은 16, 17, 18, 19, 20, 21이며 셀 크기는 181x181입니다.

아직 스프라이트를 수정하거나 생성하지 마세요. 먼저 다음 결과만 만들어 주세요.
1. Tsuki 16~21 각 프레임의 골반-무릎-발목 연결 분석
2. 해부학적 오른쪽 다리는 빨간색, 왼쪽 다리는 청록색으로 표시한 주석 이미지
3. 각 프레임의 접지 발과 공중 발을 정리한 표
4. 16번이 왜 오른발 시작인지 시각적 근거 설명
5. 현재 Yuki가 Tsuki와 다르게 보이는 정확한 프레임과 연결 부위 설명

분석 결과를 사용자에게 보여 주고 승인을 받은 후에만 실제 Yuki 프레임 제작 계획으로 넘어가 주세요.
```

## 10. GPT에게 전달할 제작 요청문

분석 단계에서 사용자가 좌우 다리 판정을 승인한 뒤에만 아래 요청문을 사용하십시오.

```text
승인된 Tsuki 좌우 다리 추적표를 기준으로 Yuki Run 16~21을 다시 제작해 주세요.

필수 규칙:
- Tsuki와 동일한 해부학적 발 순서를 사용합니다.
- 16번은 승인된 오른발 시작 자세입니다.
- 각 프레임에서 오른쪽 다리와 왼쪽 다리를 골반부터 발목까지 동일하게 추적합니다.
```
