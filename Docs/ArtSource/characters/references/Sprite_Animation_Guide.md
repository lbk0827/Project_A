# 캐릭터 스프라이트 애니메이션 가이드

이 문서는 Project A의 캐릭터 스프라이트시트를 더 자연스럽고 역동적으로 만들기 위한 공통 제작 가이드다.
외부 레퍼런스 스프라이트시트가 추가될 때마다 동작 표현 방식만 분석하고, 캐릭터 디자인 품질과 형태는 현재 프로젝트의 아트 톤을 유지한다.

## 1. 목적

현재 프로젝트의 초기 히로인, 츠키, 유키 스프라이트시트는 캐릭터 퀄리티와 실루엣은 좋지만 일부 이동 동작이 실제 보행/질주 원리처럼 왼발과 오른발을 명확히 교차하는 구조는 아니다.
앞으로 제작할 캐릭터는 다음 목표를 가진다.

- 현재 프로젝트 캐릭터의 얼굴, 비율, 의상 밀도, 렌더링 품질을 유지한다.
- 외부 레퍼런스에서는 스타일을 복사하지 않고 동작 설계 원리만 참고한다.
- `Idle`, `Walk`, `Run`, `Attack`, `Hit`, `Dead`의 프레임 역할을 먼저 설계한 뒤 이미지를 제작한다.
- 애니메이션으로 재생했을 때 잘림, 크기 튐, 중심점 흔들림, 방향 오류가 보이지 않게 한다.
- Godot 런타임에서 동일한 셀 크기와 동일한 캐릭터 기준점을 유지한다.

## 2. 레퍼런스 사용 원칙

레퍼런스 스프라이트시트는 "학습 데이터"가 아니라 "동작 분석 자료"로 취급한다.

- 참고 대상: 발 접지, 무게중심, 팔 흔들림, 머리카락/치마 후행, 공격 예비동작, 회수동작, 피격 반응의 타이밍
- 유지 대상: Project A 캐릭터의 얼굴, 체형, 의상, 무기, 색상, 선화 밀도
- 금지 대상: 외부 캐릭터의 얼굴, 의상, 장식, 독자적인 시각 정체성을 그대로 가져오는 것
- 기록 방식: 레퍼런스별로 "무엇을 배웠는지"와 "우리 프로젝트에 어떻게 변환할지"를 문장으로 남긴다.

참고 이미지를 생성 또는 리터칭에 사용할 때는 역할을 명확히 구분한다.

- `identity reference`: 우리 캐릭터 외형 고정용
- `motion reference`: 동작 흐름과 프레임 역할 참고용
- `timing reference`: 몇 프레임에 어떤 사건이 일어나는지 참고용
- `silhouette reference`: 작은 화면에서 읽히는 자세 참고용

## 3. 공통 프레임 품질 기준

모든 캐릭터 스프라이트는 다음 기준을 통과해야 한다.

- 프레임별 캐릭터 높이 차이가 의도 없이 크게 튀지 않는다.
- 발바닥 기준선 또는 몸 중심 기준점이 애니메이션 중 과하게 흔들리지 않는다.
- 머리, 머리카락, 손, 발, 무기, 이펙트가 셀 경계에 잘리지 않는다.
- 진행 방향과 얼굴/상체/발끝 방향이 서로 충돌하지 않는다.
- 루프 애니메이션은 마지막 프레임에서 첫 프레임으로 돌아갈 때 자세가 끊기지 않는다.
- 공격 애니메이션은 `예비동작 -> 타격 순간 -> 후속 관성 -> 회수`가 읽힌다.
- 피격 애니메이션은 맞은 방향, 밀림, 회복 또는 다운 전환이 읽힌다.

## 4. Idle 기준

`Idle`은 제자리에서 살아 있는 느낌을 주는 대기 동작이다.
큰 자세 변화보다 작은 호흡, 시선, 머리카락, 옷자락 움직임이 중요하다.

권장 구조:

| 단계 | 역할 | 체크 포인트 |
| --- | --- | --- |
| 1 | 기본 자세 | 캐릭터 정체성이 가장 잘 보이는 포즈 |
| 2 | 숨 들이마심 | 어깨와 가슴이 아주 작게 상승 |
| 3 | 숨 내쉼 | 머리카락과 옷자락이 한 박자 늦게 내려옴 |
| 4 | 기본 자세 복귀 | 1번 프레임과 자연스럽게 연결 |

주의사항:

- 제자리 대기인데 발이 크게 움직이면 안 된다.
- 상체가 좌우로 과하게 흔들리면 술 취한 듯 보일 수 있다.
- 프레임 수가 적을수록 몸통보다 머리카락/장식의 미세 움직임이 중요하다.

## 5. Walk 기준

`Walk`는 낮은 속도의 이동 동작이다.
Run보다 보폭이 작고, 항상 한쪽 발이 지면에 닿아 있는 인상이 필요하다.

권장 8프레임 구조:

| 단계 | 역할 | 체크 포인트 |
| --- | --- | --- |
| 1 | 왼발 접지 | 왼발이 앞에 있고 오른팔이 앞쪽 |
| 2 | 몸 하강 | 체중이 왼발 위로 이동 |
| 3 | 지나가기 | 오른발이 몸 아래를 통과 |
| 4 | 밀기 | 왼발이 뒤로 밀고 오른발 전진 |
| 5 | 오른발 접지 | 오른발이 앞에 있고 왼팔이 앞쪽 |
| 6 | 몸 하강 | 체중이 오른발 위로 이동 |
| 7 | 지나가기 | 왼발이 몸 아래를 통과 |
| 8 | 밀기 | 오른발이 뒤로 밀고 왼발 전진 |

주의사항:

- 같은 다리만 앞으로 나오는 프레임이 반복되면 걷는 느낌이 사라진다.
- 팔은 다리와 반대로 흔들려야 자연스럽다.
- 치마와 머리카락은 몸보다 약간 늦게 따라와야 한다.

## 6. Run 기준

`Run`은 Walk보다 보폭이 크고, 공중에 뜨는 순간이 들어가야 역동적으로 보인다.
Project A의 기존 주요 캐릭터 시트는 완전한 좌우 교대 Run이 아니므로, 앞으로 새 캐릭터를 만들 때는 아래 구조를 기준으로 삼는다.

권장 8프레임 구조:

| 단계 | 역할 | 체크 포인트 |
| --- | --- | --- |
| 1 | 왼발 접지 | 왼발이 앞쪽 지면에 닿고 몸은 진행 방향으로 기울어짐 |
| 2 | 왼발 체중 | 몸이 낮아지고 접지한 발이 몸 아래로 들어옴 |
| 3 | 왼발 밀기 | 왼발이 뒤로 밀며 추진력을 만듦 |
| 4 | 공중 전환 | 양발이 지면에서 떨어지고 오른발이 앞으로 나옴 |
| 5 | 오른발 접지 | 오른발이 앞쪽 지면에 닿음 |
| 6 | 오른발 체중 | 몸이 낮아지고 접지한 발이 몸 아래로 들어옴 |
| 7 | 오른발 밀기 | 오른발이 뒤로 밀며 추진력을 만듦 |
| 8 | 공중 전환 | 양발이 지면에서 떨어지고 왼발이 앞으로 나옴 |

Run 검수 체크:

- 왼발과 오른발이 번갈아 앞으로 나온다.
- 접지한 발은 프레임이 진행될수록 캐릭터 몸 아래를 지나 뒤로 간다.
- 얼굴, 가슴, 무릎, 발끝은 기본적으로 진행 방향을 향한다.
- 머리카락과 코트/치마는 진행 반대 방향으로 흐른다.
- 4번과 8번의 공중 전환 프레임이 루프를 부드럽게 이어준다.
- 캐릭터의 키와 중심점이 프레임마다 과하게 달라지지 않는다.

자주 생기는 문제:

- 접지 발이 앞으로 미끄러져 뒤로 달리는 것처럼 보임
- 얼굴은 오른쪽, 다리 추진은 왼쪽처럼 방향이 충돌함
- 한쪽 다리만 반복적으로 올라가 제자리 점프처럼 보임
- 머리카락 방향이 속도감을 거꾸로 만듦

## 7. Attack 기준

`Attack`은 무기/주력 액션에 따라 프레임 역할을 먼저 정한다.
모모카처럼 발차기가 주력인 캐릭터는 타격 궤적을 크게 그리기보다, 다리를 접고 펴고 회수하는 신체 흐름이 자연스러워야 한다.

권장 구조:

| 단계 | 역할 | 체크 포인트 |
| --- | --- | --- |
| 1 | 예비동작 | 무게중심이 낮아지고 공격 방향이 예고됨 |
| 2 | 장전 | 팔/다리/무기가 몸 쪽으로 모임 |
| 3 | 발사 | 공격 부위가 빠르게 뻗음 |
| 4 | 타격 | 가장 선명한 실루엣, 판정 타이밍 |
| 5 | 후속 관성 | 머리카락/옷/무기가 한 박자 늦게 따라옴 |
| 6 | 회수 | 공격 부위가 몸 쪽으로 돌아옴 |
| 7 | 균형 회복 | 다음 행동으로 이어질 자세 |
| 8 | 기본 자세 복귀 | Idle 또는 Run과 연결 가능 |

주의사항:

- 타격 프레임만 크거나 작으면 공격이 튄다.
- 이펙트가 캐릭터 본체를 가리면 판정 방향이 읽히지 않는다.
- 예비동작 없이 타격만 나오면 힘이 없어 보인다.
- 회수 프레임이 없으면 애니메이션이 끊긴다.

## 8. Hit 기준

`Hit`은 짧지만 방향과 충격이 명확해야 한다.

권장 구조:

| 단계 | 역할 | 체크 포인트 |
| --- | --- | --- |
| 1 | 피격 순간 | 머리와 상체가 타격 반대 방향으로 꺾임 |
| 2 | 밀림 | 발 또는 몸 중심이 뒤로 이동 |
| 3 | 버팀 | 팔/무릎이 균형을 잡음 |
| 4 | 회복 또는 다운 전환 | 다음 상태로 자연스럽게 이어짐 |

주의사항:

- 단순히 몸을 작게 줄이면 피격이 아니라 축소처럼 보인다.
- 얼굴 방향과 밀리는 방향이 충돌하면 어색하다.
- Dead로 이어지는 경우, 마지막 Hit 프레임과 첫 Dead 프레임의 높이 차이를 확인한다.

## 9. Dead / Down 기준

`Dead` 또는 `Down`은 자세 변화가 커서 프레임 크기 차이가 생기기 쉽다.
누운 프레임은 높이가 낮아져도 괜찮지만, 폭과 기준점이 안정적으로 유지되어야 한다.

검수 기준:

- 넘어지는 방향이 앞 프레임에서 예고된다.
- 바닥에 닿은 뒤 몸이 과하게 튀어 오르지 않는다.
- 누운 프레임의 머리카락, 발, 무기가 셀 밖으로 나가지 않는다.
- 다운 루프가 필요하면 마지막 프레임은 안정된 정지 자세여야 한다.

## 10. 제작 전 프롬프트 체크리스트

이미지 생성 또는 리터칭 전에 아래 내용을 프롬프트에 반드시 분리해서 적는다.

```text
Character identity:
- 얼굴, 머리색, 헤어스타일, 눈 색, 의상, 무기, 체형

Motion reference:
- 참고할 동작의 프레임 역할
- 발 접지, 팔 흔들림, 무게중심, 머리카락/의상 후행

Sheet layout:
- 열 x 행
- 셀 크기
- 전체 프레임 수
- row-major 순서
- 셀 경계 침범 금지

Animation mapping:
- Idle: frame range
- Walk: frame range
- Run: frame range
- Attack: frame range
- Hit: frame range
- Dead: frame range

Constraints:
- 프로젝트 캐릭터 정체성 유지
- 레퍼런스 캐릭터 외형 복사 금지
- 동일한 캐릭터 크기와 기준점 유지
- 잘린 머리카락, 손, 발, 무기 금지
- 텍스트, 로고, 워터마크 금지
```

## 11. QA 체크리스트

스프라이트시트를 적용하기 전에 다음 자료를 생성해 확인한다.

- 전체 스프라이트시트 미리보기
- 프레임별 바운딩 박스 리포트
- 바운딩 박스 표시 이미지
- `Idle`, `Walk`, `Run`, `Attack`, `Hit`, `Dead` GIF
- Godot 씬 로드 확인

검수 질문:

- 프레임이 셀 안에서 잘리지 않았는가?
- 특정 프레임만 과하게 작거나 큰가?
- 루프 시작과 끝이 이어지는가?
- Run에서 왼발/오른발이 교차하는가?
- 공격은 예비동작과 회수동작이 있는가?
- 피격/다운은 상태 전환이 자연스러운가?
- 실제 게임 배율에서 얼굴과 주요 실루엣이 읽히는가?

## 13. 현재 프로젝트 기준 메모

- 초기 히로인, 츠키, 유키는 캐릭터 외형 품질과 런타임 안정성의 기준으로 삼는다.
- 기존 Run 프레임은 반드시 해부학적 좌우 교대 기준으로 간주하지 않는다.
- 츠키/유키/모모카 작업에서 확인한 문제는 "좋은 외형"과 "좋은 동작"이 별도 검수 축이라는 점이다.
- 앞으로는 외형 기준 이미지와 동작 기준 이미지를 분리해서 제공하고, 프롬프트에서도 역할을 분리한다.
- 제작 결과는 바로 채택하지 않고 GIF 재생과 바운딩 박스 검사 후 런타임에 연결한다.

## 14. 레퍼런스 분석 기록

### REF-001: 장발 총기 여학생 풀 모션 시트

- 원본 파일: `Docs/ArtSource/characters/references/source_sheets/ref_001_anime_gunner_full_motion.png`
- 캐릭터 유형: 장발 여학생, 권총 액션, 횡스크롤 격투/액션 게임형 픽셀 스프라이트
- 유용한 동작: Walk, Run, Jump, Fall, Kick, Shoot, Hit, Down, Get-up
- 분석 목적: 외형 복사가 아니라 동작 흐름, 접지, 후행 움직임, 프레임 밀도를 참고한다.

좋은 점:

- 긴 머리카락이 몸보다 늦게 따라오며 속도와 방향을 잘 보여준다.
- Walk/Run에서 발 아래 그림자가 접지 타이밍을 읽기 쉽게 만든다.
- 점프 동작은 `웅크림 -> 상승 -> 공중 정점 -> 하강 -> 착지`가 분리되어 있다.
- 공격 동작은 예비동작과 회수동작이 있어 타격 프레임이 갑자기 튀지 않는다.
- 다운/기상 동작은 몸의 높이가 단계적으로 바뀌어 상태 전환이 자연스럽다.
- 같은 캐릭터라도 정면, 측면, 후면, 숙임, 공중 자세가 다양해 실루엣 라이브러리로 가치가 높다.

우리 프로젝트에 변환할 규칙:

- 장발 캐릭터는 머리카락을 별도 후행 덩어리처럼 생각하고, 몸통보다 1프레임 늦게 흐르게 설계한다.
- Run은 최소 `접지 -> 체중 하강 -> 밀기 -> 공중 전환`을 좌우 한 번씩 포함한 8프레임 기준으로 만든다.
- Jump 계열은 한 장으로 처리하지 않고, 준비/상승/정점/하강/착지를 분리한다.
- 발 아래 그림자 또는 기준선을 QA 이미지에서 함께 확인해 접지 흔들림을 잡는다.
- 공격은 타격 포즈만 만들지 않고, 공격 전 몸을 모으는 프레임과 공격 후 균형 회복 프레임을 포함한다.
- 피격과 다운은 캐릭터 크기가 작아지는 문제가 생기기 쉬우므로, 실제 몸의 바운딩 박스와 기준점을 별도 검수한다.

복사하면 안 되는 점:

- 캐릭터 얼굴, 교복 형태, 총기, 색상, 픽셀아트 렌더링 스타일은 Project A 캐릭터에 직접 가져오지 않는다.
- Project A는 더 큰 셀과 고해상도 일러스트풍 캐릭터이므로, 픽셀 단위 포즈를 그대로 옮기지 않는다.
- 총기 액션은 총을 쓰는 캐릭터에게만 적용하고, 검/발차기 캐릭터에는 몸통 회전과 팔 균형만 참고한다.

추가 QA 메모:

- 이 시트는 한 이미지 안에 여러 동작이 조밀하게 들어 있어 자동 격자 분할용으로는 부적합하다.
- 분석용으로는 동작별 스트립을 수동 분리하거나, 필요한 구간만 잘라 별도 참고 이미지로 만드는 편이 좋다.
- 추후 레퍼런스가 늘어나면 `Run`, `Jump`, `Attack`, `Hit`별 베스트 프레임 흐름을 별도 비교표로 만든다.
