# Combat Prototype Roadmap

## 목적

카드 조작 프로토타입을 실제 전투 규칙과 연출로 확장하기 위한 우선순위를 정리한다.

## 우선순위

1. 전투 데이터 구조 분리
- 플레이어, 몬스터, 카드 데이터를 `main.gd` 하드코딩에서 Godot `Resource(.tres)`로 분리한다.
- 현재 프로토타입 수치는 유지하되 Inspector에서 조정 가능하게 만든다.
- 이후 Google Spreadsheet, JSON, CSV 기반 데이터 파이프라인으로 확장 가능한 구조를 유지한다.

2. 카드 효과 계산 규칙 정리
- 공격, 방어, 드로우, 에너지 획득의 기본 처리 규칙을 명확히 한다.
- 카드별 `match id` 분기를 줄이고 효과 데이터 기반 처리로 확장할 준비를 한다.

3. 전투 HUD 추가
- 플레이어 HP, 블록, 에너지와 몬스터 HP, 블록, 의도를 화면에 표시한다.
- 데이터 변경이 플레이 중 바로 검증되도록 최소 UI를 먼저 만든다.

4. 플레이어 공격 연출 연결
- 공격 카드 사용 시 플레이어 이동, 공격 애니메이션, 몬스터 피격, 복귀 흐름을 만든다.
- 데미지 처리는 연출 타이밍에 맞춰 적용할 수 있게 정리한다.

5. 몬스터 턴 연출 연결
- 턴 종료 후 몬스터 이동, 공격, 플레이어 피격, 복귀 흐름을 만든다.
- 몬스터 의도 데이터와 연출을 연결한다.

6. 데이터 파이프라인 고도화
- Google Spreadsheet에서 CSV/JSON으로 export한 데이터를 Godot에서 사용할 수 있게 변환한다.
- 프로토타입 단계에서는 로컬 `.tres`를 기준으로 하고, 밸런싱 규모가 커질 때 자동 변환을 붙인다.

## Google Spreadsheet 연동 메모

가능하다. 추천 방식은 다음과 같다.

1. 스프레드시트를 기획 원본으로 사용한다.
2. Google Sheet를 CSV 또는 JSON으로 export한다.
3. Godot Editor import 스크립트나 별도 변환 스크립트로 `res://data/**/*.tres`를 생성한다.
4. 런타임에서는 네트워크로 시트를 직접 읽지 않고, 프로젝트에 포함된 로컬 데이터를 사용한다.

이 방식이 좋은 이유는 오프라인 실행, export 안정성, 버전 관리, 밸런스 변경 리뷰가 모두 쉬워지기 때문이다.
